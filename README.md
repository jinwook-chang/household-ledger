# 가계부

매월 **21일~다음 달 20일**, 원화(KRW), 한국 시간(Asia/Seoul) 기준.

## 기록 방법
이 대화에 `오늘 점심 12000원, 커피 4500원`처럼 적으면 거래내역과 해당 기간 결산을 GitHub에 저장함.
거래 기록마다 실제 저장 성공을 확인한 뒤 저장 완료와 기간 누적 지출을 알려줌.
은행·카드 자동 연동이나 대화 밖의 자동 수집은 설정되지 않았음.

## 파일
- `data/transactions.csv`: 전체 거래 원본. 한 행에 거래 한 건.
- `reports/YYYY-MM-DD_YYYY-MM-DD.md`: 21일~20일 기간별 결산.
- `config.json`: 기간·분류·통화 설정.

## 기준
- 최초 기간: 2026-10-21~2026-11-20. 기간 이름은 시작일과 종료일을 모두 씀.
- 21일은 새 기간, 20일은 이전 기간에 포함. 연말에도 동일.
- 사용자가 새로 제공한 실제 거래만 기록. 예전 대화의 월급·고정비·투자액은 자동 등록하지 않음.
- 날짜 없는 일반적인 당일 지출은 메시지를 받은 한국 날짜로 기록. 애매한 과거 거래 날짜나 금액은 확인.
- 금액은 원 단위 양의 정수. 금액 열에는 쉼표와 원 기호를 넣지 않음.
- 유형: 수입, 지출, 환불, 저축, 저축회수, 투자, 투자회수, 이체.
- 순소비지출 = 지출 - 환불. 저축·투자는 소비와 분리.
- 현금흐름 순증감 = 수입 + 환불 + 저축회수 + 투자회수 - 지출 - 저축 - 투자. 이체 제외.
- 기초잔액·예산은 미설정. 계산된 현금흐름을 실제 통장 잔액이나 남은 예산으로 표현하지 않음.
- 카드 사용은 사용일에 지출 기록. 이미 기록한 카드 이용액의 카드대금 결제는 이체로 기록해 이중 집계 방지.
- 선불 충전(스타벅스·교통카드 등)은 충전 시 지출로 기록하고 해당 잔액 사용분은 다시 지출로 집계하지 않음.
- 환불은 받은 날짜에 환불로 기록하고 원거래 ID를 연결. 원거래 내역은 유지.
- 저축·투자 원금 회수는 수입과 분리. 수익·손실 구분이 없으면 임의 추정하지 않음.
- 결제수단·메모가 없으면 빈칸. 분류가 불명확하면 기타로 기록하고 근거 없이 구체화하지 않음.

## CSV 열
`id,date,period_start,period_end,type,category,description,amount_krw,payment_method,related_id,note`

- ID는 `YYYYMMDD-001` 형태. 기존 ID와 중복되지 않게 부여.
- 설명과 메모에 쉼표·따옴표·줄바꿈이 있으면 CSV 규칙에 맞게 따옴표 처리.
- 문자열이 =, +, -, @로 시작하면 스프레드시트에서 수식으로 실행되지 않도록 앞에 작은따옴표 추가.
- 동일 날짜·유형·금액·설명이 반복되면 기존 내역과 대조. 중복 의심만으로 임의 삭제하거나 재등록하지 않음.

## 저장·수정 절차
1. 기록 전 최신 설정과 거래 파일을 읽음.
2. 신규 거래를 추가하거나 요청받은 거래를 ID로 찾아 수정. 수정·삭제는 커밋 이력에 남김.
3. 영향받는 기간 결산을 다시 계산. 데이터와 결산을 가능하면 같은 커밋에 저장.
4. 기존 파일·기록을 보존하고 동시 변경 시 최신 내용을 다시 읽어 반영. 강제 덮어쓰기 금지.
5. 저장 결과를 확인한 뒤에만 저장 완료라고 알림. 실패 시 미저장 상태를 명시.
